# پرداخت کارت‌به‌کارت و اعتبار ارزیابی

قیمت‌گذاری نسخهٔ فعلی:

| بسته | اعتبار ارزیابی | مبلغ | تخفیف نسبت به خرید تکی |
|---|---:|---:|---:|
| تکی | ۱ | ۶۰۰٬۰۰۰ تومان | — |
| سه‌تایی | ۳ | ۱٬۵۰۰٬۰۰۰ تومان | ۱۷٪ |
| شش‌تایی | ۶ | ۲٬۷۰۰٬۰۰۰ تومان | ۲۵٪ |
| دوازده‌تایی | ۱۲ | ۴٬۸۰۰٬۰۰۰ تومان | ۳۳٪ |

هر نصب دو ارزیابی رایگان دارد. پاسخ‌ها و نتایج ارزیابی روی دستگاه می‌مانند. برای خرید، شمارهٔ همراه، شناسهٔ پیگیری و تصویر رسید به سرور پرداخت ارسال می‌شود.

## راه‌اندازی مدیر

پیش از دریافت هر پرداخت، API را روی میزبان HTTPS با دیسک پایدار اجرا کنید. در متغیرهای محیطی سرور تنظیم کنید:

```sh
PAYMENT_CARD_NUMBER='شماره کارت ۱۶ رقمی'
PAYMENT_CARD_HOLDER='نام دارنده کارت'
PAYMENT_BANK_NAME='نام بانک'
PAYMENT_ADMIN_TOKEN='یک رمز تصادفی بلند و محرمانه'
PAYMENTS_DATA_DIR='/مسیر/دائمی/داده'
```

`PAYMENT_ADMIN_TOKEN` باید حداقل ۳۲ نویسهٔ تصادفی داشته باشد؛ هرگز آن را در APK، مخزن، پیام به مشتری یا URL قرار ندهید. شماره کارت باید ۱۶ رقم معتبر باشد. پایگاه SQLite و تصویر رسید در پوشهٔ `PAYMENTS_DATA_DIR` ذخیره می‌شوند؛ از این پوشه پشتیبان رمزگذاری‌شده و منظم تهیه کنید. خرید تا زمانی که همهٔ تنظیم‌های کارت و مدیر تنظیم نشده باشند، در اپ غیرفعال است.

در حال حاضر `apiBaseUrl` اپ خالی است: پیش‌نمایش وب API نسبی همان میزبان را به‌کار می‌برد؛ برای APK باید آدرس API عمومی HTTPS در `mobile/app.json` و سپس بیلد جدید تنظیم شود. این مخزن به‌تنهایی میزبان تولیدی یا درگاه بانکی را فراهم نمی‌کند.

## بررسی و تأیید رسید

پس از تنظیم API، پنل مدیر در `https://دامنه-شما/admin/payments` در دسترس است. رمز مدیر فقط در نشست همان مرورگر نگه داشته می‌شود؛ پنل، فهرست رسیدها و تصویر هر رسید را از API امن می‌گیرد. مدیر با توکن از این APIها نیز استفاده می‌کند:

- `GET /api/admin/payments` — فهرست درخواست‌های در انتظار
- `GET /api/admin/payments/{request_id}/receipt` — دریافت تصویر رسید
- `POST /api/admin/payments/{request_id}/approve` — تأیید و افزودن اعتبار به همان نصب
- `POST /api/admin/payments/{request_id}/reject` — رد درخواست

نمونهٔ درخواست:

```sh
curl -H "X-Admin-Token: $PAYMENT_ADMIN_TOKEN" https://api.example.com/api/admin/payments
curl -H "X-Admin-Token: $PAYMENT_ADMIN_TOKEN" -X POST \
  https://api.example.com/api/admin/payments/REQUEST_UUID/approve
```

تأیید پرداخت با مبلغ، شمارهٔ کارت مقصد و مرجع بانکی تطبیق داده شود. هر شناسهٔ پیگیری فقط یک‌بار قابل ثبت است. شناسهٔ نصب تصادفی است و در این نسخه هویت کاربر را بین دستگاه‌های مختلف همگام نمی‌کند. اعتبارها روی همان نصب فعال می‌شوند.

## نکات پیش از فروش

- نسخهٔ فعلی از پرداخت بازار/مایکت/گوگل‌پلی استفاده نمی‌کند؛ این بخش برای فروش مستقیم با رسید کارت‌به‌کارت است.
- پیش از انتشار عمومی، API باید HTTPS و پایگاه داده/تصاویر باید روی ذخیره‌ساز پایدار باشد، توکن مدیر قوی تنظیم شود و تست پشتیبان‌گیری انجام شود.
- پرداخت دستی نیاز به بررسی انسانی دارد؛ تا تأیید مدیر، اعتبار اضافه نمی‌شود.
- دو ارزیابی رایگان در حالت آفلاین با شمارندهٔ محلی محدود می‌شوند. محدودسازی رایگان آفلاین، سامانهٔ ضدتقلب حساب کاربری نیست؛ هر نصبی شناسهٔ مستقل دارد.
