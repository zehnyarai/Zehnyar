# دریافت فایل نصب آنلاین پستینو

**این مسیر فقط برای نسخه آیندهٔ متصل به API است. برای نصب مستقل و بدون هزینه، [راهنمای نسخه مستقل](free-installation.md) را بخوانید؛ راه‌اندازی سرور لازم نیست.**

**وضعیت نسخه آنلاین:** سرور دائمی فعال نشده و هنوز APK آنلاین ساخته نشده است. `render.yaml` و workflow ساخت فایل نصب آماده‌اند. پیش‌نمایش Arena موقت است؛ آن را داخل APK قرار نمی‌دهیم.

## ۱. انتشار سرور در حساب خودتان

از [داشبورد Render](https://dashboard.render.com/) وارد حساب خودتان شوید. این مرحله نیاز به تأیید شما در حساب میزبانی دارد؛ هیچ رمز یا کلیدی نباید در گفتگو ارسال شود.

برای این پایلوت، یکی از دو مسیر:

### Blueprint

`New → Blueprint`، مخزن عمومی `zehnyarai/Zehnyar`، شاخه **`arena/e819b607-zehnyar`** و فایل `render.yaml` را انتخاب کنید. بررسی کنید شاخه main یا شاخه برنامه دیگری انتخاب نشده باشد. سپس تنظیمات و شرایط پلن را در حساب خودتان بررسی و انتشار را تأیید کنید.

### Web Service

اگر انتخاب شاخه Blueprint در رابط فعلی در دسترس نبود: `New → Web Service`، همان مخزن و همان شاخه، محیط **Docker** و فایل `./Dockerfile`. متغیرهای اولیه:

- `DEMO_MODE=true`
- `COOKIE_SECURE=true`
- `ZARINPAL_SANDBOX=true`
- `PORT=8000`
- Health check: `/api/health`

Render پس از ایجاد سرویس، URL واقعی HTTPS را نشان می‌دهد. کد از `RENDER_EXTERNAL_URL` استفاده می‌کند؛ نام دامنه از قبل حدس زده نمی‌شود. برای دامنه شخصی، `PUBLIC_BASE_URL` را در پنل میزبان تنظیم کنید.

**این تنظیمات برای تست اولیه‌اند.** طرح free، اگر در حساب شما در دسترس باشد، ممکن است خاموشی خودکار/تأخیر شروع داشته باشد و دیسک آن دائمی نیست. داده‌ها ممکن است با restart یا deploy حذف شوند. برای اطلاعات واقعی باغدار، عکس و پرداخت، ذخیره‌سازی دائمی و زیرساخت مناسب لازم است؛ قبل از تغییر پلن هزینه را خودتان تأیید کنید. تغییر پلن یا خرید سرویس از طرف شما انجام نشده است.

## ۲. فرستادن آدرس عمومی، نه اطلاعات محرمانه

بعد از Live شدن سرویس، فقط URL عمومی HTTPS آن را برای ادامه ساخت APK ارسال کنید. کلید بینایی، Merchant ID، رمز مدیر یا رمز Render را در گفتگو ارسال نکنید. فعال‌سازی سرویس‌های واقعی جدا از انتشار رابط و API است.

## ۳. ساخت APK تست

workflow `.github/workflows/pestino-apk.yml` فقط برای شاخه همین جلسه است. تا تنظیم `PESTINO_SERVER_URL` در GitHub Actions Variables، ساخت APK عمداً **skip** می‌شود؛ وضعیت workflow بدون آدرس به معنی ساخته شدن فایل نیست.

بعد از ثبت URL واقعی، یک commit جدید روی همین شاخه، build را اجرا می‌کند. پیش از کامپایل، URL و هویت سرور با `/api/health` و `/api/openapi.json` بررسی می‌شوند. سپس JDK 21، SDK 36، Gradle و Capacitor فایل `Pestino-0.1.0-test.apk` را می‌سازند، امضا و package ID بررسی و فایل در artifact با نام `pestino-test-apk` قرار می‌گیرد.

فایل به‌صورت **debug-signed برای تست نصب** است؛ انتشار در بازار/مایکت نیاز به کلید خصوصی و ثابت release، آزمون گوشی واقعی، App Links پرداخت، سیاست حریم خصوصی و تأیید علمی دارد. هیچ release عمومی یا نسخه latest به جای برنامه‌های قبلی این مخزن منتشر نمی‌شود.

## محدودیت‌ها

- سرویس عکس و پرداخت هنوز بدون تنظیم و آزمون واقعی غیرفعال‌اند.
- تصویر نمونه تشخیص عکس شما نیست و مقاله‌ها تأیید علمی محلی ندارند.
- pipeline جدید هنوز به دلیل نبود URL دائمی، APK آنلاین تولید نکرده است.
- انتشار سرور در Render و نصب APK روی دستگاه واقعی در این محیط انجام نشده‌اند.
