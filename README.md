# پستینو | Pestino

## نصب ساده بدون سرور و بدون هزینه

حالت مستقل برای APK اندروید و وب‌اپ قابل افزودن به صفحه اصلی آیفون آماده شده است: [`docs/free-installation.md`](docs/free-installation.md). این نسخه باغ/تقویم/دانشنامه/عکس را محلی نگه می‌دارد و تحلیل هوشمند یا پرداخت ندارد. برای آن نیازی به راه‌اندازی Render نیست. فایل‌های نصب فقط پس از موفقیت واقعی build تحویل می‌شوند؛ منبع Android یا ZIP، جای APK نیست.

همراه فارسی و راست‌به‌چپ باغداران پسته: مدیریت باغ، غربالگری تصویر، دانشنامه، تقویم مراقبت و مدیریت پرداخت. رابط React/TypeScript، API با FastAPI و پروژه اندروید با Capacitor.

> **وضعیت: پایلوت، نه محصول تأییدشده برای عرضه سراسری.** رابط و مسیرهای پایه کار می‌کنند؛ دقت تشخیص در ایران اعتبارسنجی نشده است. سرویس بینایی و درگاه بدون تنظیم کلیدهای واقعی غیرفعال‌اند. APK مستقل ۰.۲.۰ با طرح جدید ساخته/تحویل شده و روی API 24/35 نصب و صفحه فارسی‌اش نمایش داده شده است؛ مسیرهای سروری جدید هم اضافه شده‌اند. اتصال زنده سرویس‌ها در این محیط آزمایش نشده است. وضعیت فایل نصب جدید در `installers/BUILD.txt` ثبت می‌شود.

## قابلیت‌های پیاده‌سازی‌شده

- طراحی مرجع تصاویر: منوی افقی، نشان برگ سبز، زمینه روشن، کارت‌ها و تمام فرم‌های خاک/آب، دیوار تجربه، بازار/اقلیم و اعتبار/رسید. دفتر باغ، دانشنامه و پشتیبان نیز حفظ شده‌اند.
- ثبت‌نام/ورود با ایمیل، رمز `scrypt`، نشست HTTP-only، کنترل مالکیت تمام باغ‌ها، عکس‌ها، گزارش‌ها و یادآورها.
- ثبت، ویرایش، حذف و جستجوی باغ؛ استان‌های ایران، شهر، رقم، سن، مساحت و آبیاری.
- عکس از دوربین/گالری/رهاکردن فایل؛ پشتیبانی JPG/PNG/WebP تا ۶ مگابایت، تا چهار زاویه مرتبط؛ تصحیح جهت و حذف EXIF/GPS پیش از ذخیره و ارسال.
- آداپتور بینایی Gemini، Groq، OpenAI یا Ollama با سرور صریح با مدل قابل تنظیم، پاسخ JSON اعتبارسنجی‌شده، تفکیک مشاهده/فرضیه/اقدام/آزمایش؛ محدودیت اعتبار سمت سرور و عدم کسر اعتبار در خطای سرویس.
- ۲۶ راهنمای آموزشی اولیه درباره آفات، بیماری‌ها، آب و خاک، تغذیه، اقلیم، هرس، گرده‌افشانی و برداشت، با منابع و وضعیت بازبینی. **این مجموعه جامع یا به‌روزرسانی زنده نیست.**
- آزمایش خاک و آب با واحد/روش/تاریخ، SAR/RSC از مقادیر واقعی؛ هیچ دوز کود یا تشخیص کمبود از رنگ/ppm بدون زمینه تولید نمی‌شود.
- تجربه خصوصی/در انتظار بررسی مدیر، قیمت و اقلیم دستی منبع‌دار، نه داده زنده ساختگی.
- اعتبار و رسید کارت‌به‌کارت با بانک خالی و دریافت وجه پیش‌فرض غیرفعال، تصویر خصوصی، دلیل رد و ledger اتمی/idempotent.
- جستجو، فیلتر و نشان‌گذاری روی دستگاه، گزارش متنی قابل دریافت، حذف عکس و محتوای گزارش.
- یادآورهای قابل ساخت، تکمیل و حذف؛ تقویم هفتگی و تاریخ‌های فارسی. پیامک و پوش بیرونی هنوز فعال نیستند.
- درخواست و تأیید سمت سرور پرداخت زرین‌پال V4، ثبت ریالی/نمایش تومانی، کنترل idempotency، استعلام دوباره توسط مدیر و خروجی CSV ایمن.
- جداسازی محیط Sandbox در سوابق؛ پرداخت آزمایشی درآمد واقعی محسوب نمی‌شود و پس از تغییر به محیط عملیاتی، اشتراک آزمایشی معتبر نیست.
- پنل مدیر با کنترل نقش در API. پنل عمومی نمایشی فقط داده جعلیِ برچسب‌خورده دارد، نه کاربران واقعی.
- پروژه Android با نام و آیکون پستینو، RTL، حداقل Android 7 (API 24)، Camera plugin و منابع شروع.

## طراحی جدید و محدودیت علمی

جزئیات، قراردادها و تفاوت عکس/تشخیص: [`docs/reference-design-and-science.md`](docs/reference-design-and-science.md). تحلیل واقعی مهم‌ترین بخش درخواست است و هنوز نیازمند اتصال و اعتبارسنجی مدل روی داده پسته ایران است؛ راهنمای دستی جای آن نیست. هیچ درصد دقت/اطمینان کالیبره‌نشده نمایش داده نمی‌شود.

## شروع محلی

پیش‌نیاز: Python 3.11+ و Node 22.12+.

```bash
npm ci
python -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
cp .env.example .env
```

در دو ترمینال مستقل:

```bash
.venv/bin/uvicorn main:app --host 0.0.0.0 --port 8000
```

```bash
npm run dev -- --port 5173
```

رابط روی پورت ۵۱۷۳ است. درخواست‌های `/api` با پراکسی به سرور می‌روند؛ کد مرورگر هرگز برای دسترسی به سرور به `localhost` اشاره نمی‌کند. میزبان‌های پیش‌نمایش `*.e2b.app` مجازند. مستندات API: `/api/docs`.

در حالت `DEMO_MODE=true` برای هر مرورگر مهمان، فضای نمونه جدا ساخته می‌شود. داده‌های ساخته‌شده توسط کاربر در همان نشست ذخیره می‌شوند. ثبت‌نام داده‌های نمونه را پاک و داده‌های ایجادشده توسط مهمان را حفظ می‌کند. **این محیط ذخیره‌سازی دائمی یا بکاپ محصول واقعی نیست.**

## اتصال سرویس واقعی

تنها در `.env` محلیِ خارج از Git یا تنظیمات امن میزبان سرور؛ **هرگز کلید را در چت، React، APK یا Git وارد نکنید.**

### بینایی

```dotenv
VISION_PROVIDER=groq
VISION_MODEL=<نام دقیق مدل بینایی پشتیبانی‌شده در حساب سرویس>
GROQ_API_KEY=<تنها روی سرور>
```

مدل Ollama باید جداگانه از قبل روی سرور خود مالک نصب باشد: `VISION_PROVIDER=ollama`، `VISION_MODEL` و `OLLAMA_BASE_URL=http://<میزبان قابل دسترس سرور>:11434`. نصب/اجرای مدل در این کار انجام نشده است؛ آداپتور تنظیم‌شده، اثبات کارکرد مدل نیست.

یا `VISION_PROVIDER=openai` همراه با `OPENAI_API_KEY` و `VISION_MODEL`. مدل متن‌محور مناسب عکس نیست. نام مدل پیش‌فرض عمداً مشخص نشده تا مدل بازنشسته یا متن‌محور به اشتباه فعال نشود. ابتدا با نمونه‌های واقعی و رضایت صاحبان داده اتصال را آزمایش کنید. «تنظیم شده» در پنل تنها وجود پیکربندی را نشان می‌دهد، نه صحت اتصال یا دقت تشخیص.

### Gemini — عکس و آزمایش آب/خاک

راهنمای امن: [`docs/gemini-connection.md`](docs/gemini-connection.md). پشتیبانی REST بومی و تفسیر مستقل آزمایش اضافه شده، اما اتصال زنده و اعتبارسنجی علمی هنوز انجام نشده‌اند. کلید فقط در secret سرور است؛ قرار دادن کلید/مدل به‌تنهایی درخواست بالقوه پولی را فعال نمی‌کند (`GEMINI_REQUESTS_ENABLED=false`). نمونه‌های رسمی جاری مدل reasoning `gemini-3.1-pro-preview` را معرفی می‌کنند؛ دسترسی، سهمیه و هزینه باید در حساب مالک تأیید شوند. APK مستقل ۰.۲.۰ قبلی با این تغییر به نسخه آنلاین تبدیل نمی‌شود.

### مدیر

```dotenv
ADMIN_EMAIL=<ایمیل مدیر>
ADMIN_PASSWORD=<رمز قوی حداقل ۱۲ کاراکتر>
```

در اولین اجرای API، اگر این ایمیل وجود نداشته باشد حساب مدیر ساخته می‌شود. هیچ نام کاربری/رمز پیش‌فرضی وجود ندارد. این متغیرها حساب موجود را ارتقای نقش یا تغییر رمز نمی‌دهند؛ مدیریت چرخه حساب و بازیابی رمز از نیازهای پیش از انتشار است.

### پرداخت

```dotenv
PUBLIC_BASE_URL=https://<دامنه واقعی سایت>
ZARINPAL_MERCHANT_ID=<تنها روی سرور>
ZARINPAL_SANDBOX=true
COOKIE_SECURE=true
```

مبلغ در دیتابیس و درخواست زرین‌پال **ریال (IRR)** است؛ رابط تومان نمایش می‌دهد. فروش طرح پولی تا زمان تنظیم بینایی هم مسدود است. Callback باید در اینترنت در مسیر `/api/payments/callback` قابل دسترس باشد. ابتدا Sandbox، سپس با تأیید درگاه `ZARINPAL_SANDBOX=false`. قبل از تغییر محیط، تکلیف پرداخت‌های معلق و کلید مناسب همان محیط را روشن کنید. قیمت‌ها طرح اولیه محصول‌اند و باید قبل از عرضه توسط مالک محصول تأیید شوند.

`Status=OK` یا `?payment=success` به‌تنهایی اشتراک را فعال نمی‌کند. تنها verify سرور درگاه با مبلغ و Authority ذخیره‌شده می‌تواند موفقیت را ثبت کند. بازپرداخت در پنل رسمی درگاه انجام می‌شود؛ گردش بازپرداخت، مالیات و ابطال اشتراک هنوز باید تکمیل شود.

نام محصول **پستینو | Pestino** است. شناسه پروژه پیش‌انتشار اندروید `ir.pestino.app` است. پیشوند داخلی نشست، نشان‌های ذخیره‌شده و نام مسیر/volume دیتابیس قبلی عمداً حفظ شده‌اند تا تغییر برند باعث خروج از حساب یا از دست رفتن داده‌ها نشود.

## ساخت اندروید

پیش‌نیازهای خارج از این محیط: Android Studio، JDK 21، Android SDK 36 و امکان دریافت Gradle/Maven. پروژه `android/` ساخته و همگام شده است، ساخت و امضای آزمایشی نسخه مستقل انجام می‌شود. APK قبلی ۰.۱.۱ ساخته و در شبیه‌سازها نصب/Activity آن شروع شده؛ نصب روی گوشی واقعی، دوربین و iPhone تأیید نشده‌اند. امضای ثابت فروشگاهی فراهم نشده است.

نسخه آنلاین از همان دامنه HTTPS رابط و API استفاده می‌کند تا درخواست‌ها و کوکی‌ها first-party بمانند. با URL سرور منتشرشده:

```bash
CAPACITOR_SERVER_URL=https://<دامنه واقعی سایت> npm run android:sync
npm run android:open
```

سپس در Android Studio ساخت و امضای Release APK/AAB. فایل تنظیم کپی‌شده در اندروید نادیده گرفته شده؛ در هر ساخت باید مقدار محیطی بالا را اعمال کنید. این نشانی عمومی است، نه کلید سرویس. بدون آن، بسته محلی API آنلاین ندارد و مناسب انتشار نیست. نسخه آنلاین بدون سرور منتشرشده قابل استفاده کامل نیست. نسخه مستقل جداگانه، داده را در IndexedDB داخل دستگاه نگه می‌دارد و تشخیص تصویر ندارد.

قبل از انتشار، دسترسی دوربین و لغو آن، Android WebView، شبکه ضعیف، ورود، پرداخت و بازگشت از مرورگر بیرونی را روی گوشی واقعی آزمایش کنید. Android App Links/assetlinks و دامنه واقعی برای بازگشت خودکار پرداخت به اپ هنوز باید تنظیم شوند. نشست‌ها و کلیدهای امضا را در Git قرار ندهید. تنظیمات فروشگاه، سیاست حریم خصوصی، نام بسته نهایی و امضا به عهده مرحله انتشار هستند.

## ساخت و استقرار پایلوت

```bash
npm run build
.venv/bin/uvicorn main:app --host 0.0.0.0 --port 8000 --workers 1
```

FastAPI فایل‌های `dist/` و fallback مسیرهای رابط را نیز سرو می‌کند. یا `docker compose up --build` بعد از ساخت `.env` و تنظیم HTTPS reverse proxy. Dockerfile/Compose به‌عنوان تنظیم استقرار اضافه شده‌اند؛ اجرای Docker در این محیط آزمایش نشده است.

- `DEMO_MODE=false`، HTTPS، `COOKIE_SECURE=true` و دامنه Callback صحیح.
- حجم آپلود در reverse proxy برای پرونده چهارعکسی تا ۲۴ MiB به‌علاوه سربار multipart محدود شود (هر تصویر ۶ MiB؛ رسید ۶ MiB). محدودیت واقعی byte در API برای درخواست chunked نیز وجود دارد.
- `/data` یا `storage/` باید volume دائمی با بکاپ قابل بازیابی باشد؛ DB و عکس‌ها در Git قرار نمی‌گیرند.
- **فقط یک worker/instance:** recovery وضعیت‌های processing/verifying در startup و محدودکننده درخواست برای پایلوت تک‌پردازه طراحی شده‌اند.
- اعتماد `X-Forwarded-*` فقط به reverse proxy خصوصی. CSP/HSTS، کنترل دسترسی مستندات و پایش خطا در استقرار نهایی تنظیم شوند.
- برای استفاده سراسری ایران، SQLite و rate limiter حافظه‌ای مناسب معماری نهایی نیستند: Postgres، Redis/shared rate limit، صف پردازش با lease، object storage خصوصی، مانیتورینگ و آزمون بار لازم است.

## آزمون‌ها

```bash
.venv/bin/python -m pytest -q
npm test
npm run build
```

آزمون مرورگر (API و Vite باید در حال اجرا باشند):

```bash
npx playwright install chromium
npm run test:e2e
```

برای مرورگر موجود: `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/path/to/chromium npm run test:e2e`. آزمون‌ها اتصال خارجی را mock می‌کنند و جای آزمون واقعی درگاه، دقت مدل یا تست اندروید نیستند. آزمون E2E را روی محیط توسعه اجرا کنید، نه دیتابیس محصول واقعی.

## فایل نصب آنلاین و انتشار سرور

راهنمای مرحله‌به‌مرحله: [`docs/online-installation.md`](docs/online-installation.md).

`render.yaml` برای انتشار پایلوت از شاخه همین جلسه و `.github/workflows/pestino-apk.yml` برای ساخت APK تست بعد از دریافت URL واقعی اضافه شده‌اند. تا آماده شدن سرور و ثبت `PESTINO_SERVER_URL`، فایل نصب آنلاین ساخته نمی‌شود. سرور به‌صورت خودکار از URL واقعی محیط Render استفاده می‌کند؛ پیش‌نمایش موقت Arena در APK پذیرفته نمی‌شود. تأیید حساب میزبانی، هزینه/ذخیره‌سازی دائمی و انتشار release نهایی هنوز نیازمند اقدام مالک‌اند.

## تغییر اتصال مدل و قیمت‌گذاری USD — ۲۰۲۶-۱۰-۱۱

پشتیبانی Gemini برای تصویر و تفسیر مستقل آزمایش اضافه شده؛ هنوز کلید، اتصال زنده و اعتبارسنجی علم پسته تنظیم/تأیید نشده‌اند. راهنما: [اتصال امن Gemini](docs/gemini-connection.md).

قیمت بسته‌ها می‌تواند بر مبنای USD و نرخ دستیِ معتبرِ همان روز تهران تعیین شود؛ مبلغ/نرخ از روی حدس پیش‌فرض نشده، فید خودکار ارز وجود ندارد. درخواست دریافت وجه ثبت شده، اما تا تکمیل مقصد، مدل و قیمت معتبر، **دریافت وجه خاموش** است. هر رسید مبلغ quote خودش را حفظ می‌کند. راهنما: [قیمت دلاری و دریافت وجه](docs/dollar-pricing-and-receiving.md). پیش‌نویس اطلاعات مالک در `.private/` از Git و HTTP عمومی خارج است؛ کلید واقعی در آن نیست.

تغییر کد، APK مستقل قبلی را به نصب آنلاین/پرداخت فعال تبدیل نمی‌کند. این دور: ۹۲ آزمون Python، ۴۵ آزمون TypeScript و ۱۰ سناریوی مرورگر موفق؛ Google/بانک/نرخ واقعی روز mock نشده‌اند به‌عنوان واقعیت و آزمایش زنده نشده‌اند.

## کتابخانه پژوهش — ۲۰۲۶-۱۰-۱۲

نسخه تست ۰.۳، ۲۴ رکورد پژوهشی/ترویجی منبع‌دار را جدا از ۲۶ راهنمای اولیه نمایش می‌دهد. بخش «دانشنامه ← پژوهش و نوآوری» جستجوی موضوع، نوع مطالعه، تاریخ انتشار/مرور، محدودیت و خروجی متنی دارد. خلاصه‌ها محلی همراه اپ‌اند؛ فید زنده یا دیتاست تشخیص تصویر نیستند. گزارش محدوده و استاندارد اعتماد: [مرور پژوهش پسته](docs/pistachio-research-review-2026-10-12.md). «همه پایگاه‌ها» یا بازبینی کارشناس ایران ادعا نشده است. نسخه ۰.۳، نسخه نهایی متصل به مدل یا پرداخت محسوب نمی‌شود.

## تحلیل عکس و آزمایش روی خود گوشی — ۲۰۲۶-۱۰-۱۲ (نسخه ۰.۴.۰)

مسئله: هسته اصلی برنامه «عکس از درخت در باغ → راهنمای دقیق» است، اما نسخه مستقل سرور ندارد و این محیط توسعه هم دسترسی مستقیم به API گوگل ندارد. راه‌حل بدون هزینه: خودِ اپ روی دستگاه باغدار با **کلید شخصی Google** فراخوانی می‌کند.

- فعال‌سازی: «داده‌ها و پشتیبان» → ثبت مدل و کلید شخصی → «آزمون اتصال» (فراخوانی متن‌محور، بدون مصرف عکس). تا موفق‌نشدن این آزمون، تحلیل عکس انجام نمی‌شود و نتیجه ساختگی ساخته نمی‌شود.
- کلید: فقط در حافظه همان دستگاه (localStorage)؛ داخل APK، مخزن، فایل پشتیبان و URL نیست. فقط هدر `x-goog-api-key`.
- تحلیل عکس: از صفحه اسکن، عکس به‌صورت JPEG بازتولیدشده (بدون EXIF/GPS) فرستاده می‌شود؛ پرونده عکس همیشه روی دستگاه می‌ماند، حتی اگر فراخوانی شکست بخورد.
- گاردهای سمت دستگاه: دوز/غلظت عددی، درصد دقت/اطمینان کالیبره‌نشده، شناسه راهنمای ساختگی و فرضیه برای تصویر غیرپسته رد می‌شود؛ ارقام فارسی/عربی هم پوشش دارند؛ `confidence` همیشه `null`.
- آزمایش خاک/آب: محاسبه SAR/RSC در خود اپ انجام می‌شود (نه مدل) و تفسیر متنی با همان کلید ساخته و در تاریخچه محلی ذخیره می‌شود؛ ورودی اعداد بدون رضایت آگاهانه ارسال نمی‌شود.
- محدودیت‌های صریح: نیازمند اینترنت روی گوشی و دسترسی شبکه به Google؛ نتیجه غربالگری احتمالی است، نه تشخیص قطعی؛ اعتبار علمی محلی مدل اندازه‌گیری نشده؛ سهمیه حساب خود باغدار مصرف می‌شود. پرداخت، همگام‌سازی و IPA همچنان فعال نیستند.

## پنل مدیر نسخه مستقل و اتصال مدل — نسخه ۰.۵.۰

- پنل مدیر آفلاین (`src/components/LocalAdminPanel.tsx`): ثبت کلید شخصی Google و انتخاب مدل، آزمون اتصال متن‌محور، جدول زنده وضعیت همه بخش‌ها، ثبت کارت مقصد و دفتر دریافتی دستی.
- کارت مقصد: اعتبارسنجی Luhn + نرمال‌سازی ارقام فارسی/عربی + الزام تأیید چشمی مالک، چون ترتیب گروه‌های رقم با محاسبه قابل تشخیص نیست (۶۰۶۳…۹۴۰۱ و ۹۴۰۱…۶۰۶۳ هر دو از checksum عبور می‌کنند).
- دفتر دریافتی: ثبت دستی با اعتبارسنجی مبلغ/تاریخ در خود دستگاه؛ درگاه بانکی، تأیید خودکار و اعتبار سروری همچنان وجود ندارد و به‌صراحت همین را می‌گوید.
- صفحه اعتبار در نسخه مستقل، کارت ثبت‌شده را با متن «حالت دریافت دستی» نشان می‌دهد و فرم رسید سروری را پنهان می‌کند.
- وضعیت همه بخش‌ها (فعال / نیازمند تنظیم / در این نسخه ممکن نیست) در `docs/app-capabilities-fa.md` و همان‌طور داخل برنامه.
- تست‌ها: ۷ تست جدید کارت/دفتر/جدول وضعیت، ۵ تست یکپارچه مسیرهای `/local/billing*` و یک تست Chromium از پنل مدیر تا ثبت دریافتی.
